## 1. 项目是什么

ScreenPilot 是参照开源 macOS 应用 DogSC 的 Windows 录屏与轻量视频编辑产品。用户希望功能、操作、界面与成片效果尽量对齐固定 Mac 版本，而不是做一个只保留少量功能的 MVP。

本项目是独立的 C++/Qt 实现，不是原作者的官方跨平台版本。当前优先 Windows，之后才考虑 Linux。用户明确取消了 Mac 工程格式兼容、转换与互通需求；本项目自己的工程格式仍须正常保存、重开。

用户当前的重点是**界面精美程度**。此前开发优先打通录制和编辑，导致界面更像功能面板。最近已经完成第一轮浅色整理，但距离原版完整的视觉质感仍有差距，不能把“改成浅色”视为设计完成。

用户偏好：尽快看到真实成品；验证尽量短而有效；普通可逆修改直接推进；不公开私人内容。Codex 原生子代理必须使用 `gpt-6.1-sol`；这条是现有仓库的代理约束，不代表 Claude 自身需要或能够切换成该模型。

## 3. 原版的视觉特点与当前差距

原版录制界面是紧凑的白色悬浮工具条，来源、麦克风、摄像头、系统声音、位置等动作分组清楚。原版编辑器使用浅色创作工作台，工具栏克制，中央预览占主导，左侧分类导航、右侧检查器、底部时间线各司其职。原版导出面板有明确的设置区、预览区和确认操作。

当前界面已经使用浅色、绿色强调、圆角面板和共享控件，但仍有这些改进空间：

- 录制页仍是较大的设置与预览窗口，尚未达到原版紧凑悬浮条的形态。
- 编辑器一些动作仍以文字按钮堆叠；分类栏和时间线的层级、密度与精致程度还可提高。
- 图标目前主要为 Canvas 绘制的基础线条，需要检查线宽、语义、光学对齐与统一性。
- 原版的细腻浮层、间距、字体权重、选中态、滚动体验与完整状态呈现尚未逐页对照。
- 浅色/深色切换、高对比偏好、全部DPI和无障碍尚未完整验收。

可以调整当前的色值、组件外观、页面结构及入口组织。建议从原版的比例与信息层级出发，做适合 Windows 的一致设计。保留中文界面与键盘/鼠标操作；没有必要机械复制 macOS 系统窗口装饰。

## 4. 技术与界面文件地图

应用为 C++20 / Qt 6.8.3，Qt Quick/QML，`QQuickStyle::setStyle("Basic")`。没有 Web 前端。根 `CMakeLists.txt` 通过 `qt_add_qml_module` 注册 QML；新增组件需要加入模块，并沿用现有资源别名。`StudioTheme.qml` 是单例，注册方式与普通组件不同。

| 文件 | 职责与修改注意点 |
| --- | --- |
| `app/Main.qml` | 主窗口、录制页、返回编辑、录制结果移交、关闭与未保存保护；不是只有布局 |
| `app/Editor.qml` | 编辑页、预览播放/定位、摄像头同步、检查器、工程和导出对话框；包含关键媒体逻辑 |
| `app/StudioTheme.qml` | 共享颜色与字体令牌 |
| `app/StudioIcon.qml` | Canvas 线条图标，支持 `name`/`iconName` 与 `color` |
| `app/StudioButton.qml` | Button 子类；`iconName`、`primary`、`quiet`、`danger`、`compact`，以及 checked/highlighted 状态 |
| `app/StudioComboBox.qml`、`StudioSlider.qml`、`StudioCheckBox.qml`、`StudioTextField.qml` | 标准 Qt Quick Controls 子类；保持原有属性、信号和输入语义 |
| `app/TimelineStrip.qml` | 主视频片段、缩略图、稀疏波形、选中和拖动重排 |
| `app/ManualZoomTrack.qml` | 运镜轨、移动/端点草稿、吸附、提交和取消 |
| `app/ManualFramingControls.qml` | 手动运镜参数与操作 |
| `app/BackgroundControls.qml`、`VisualSceneControls.qml` | 背景、外框与开场效果设置 |
| `app/CropEditor.qml` | 裁切草稿、确认和取消 |
| `app/ScenePresetPanel.qml` | 场景预设 |
| `app/RecentProjectsPanel.qml` | 最近工程入口，不应绕过未保存保护 |
| `app/EditorShortcuts.qml`、`ShortcutHelp.qml` | 编辑快捷键及帮助；文字输入与弹窗需阻止全局编辑快捷键 |
| `app/MemoWindow.qml` | 独立悬浮备忘录，不是普通页面内卡片 |
| `app/main.cpp` | 启动、上下文对象、媒体输入连接与现有验证入口 |

主要上下文对象包括 `recorder`、`project`、`exporter`、`cameraRecorder`、`timelineMedia`、`previewAudioProcessor`、`scenePresets`、`recentProjectsController`、`memoController`。阅读它们的头文件获取真实属性与 invokable API，不虚构替代控制器。

## 5. 已实现功能，改 UI 时不能丢

以下为已有实现，不表示所有能力都已达到 Mac 版的数值与视觉一致性：

- 屏幕/窗口录制；系统声音、可选麦克风及设备选择；保存位置；暂停/继续；停止保存；重录/丢弃；录制标记；悬浮备忘录。
- 摄像头可选录制、设备/格式选择、镜像；编辑中布局、形状、大小和同步偏移。真实摄像头硬件尚未完成验收，不能写成全面通过。
- 编辑器播放、暂停、定位、跨片段播放；片段拆分、裁短、删除、重排、变速、撤销/重做；缩略图和稀疏音频峰值。
- 可选自动运镜、手动运镜片段、焦点和曲线；轨道移动/端点调整、吸附、拆分、内部复制粘贴及属性粘贴。
- 画面比例、裁切、留白、背景颜色/图片/静音循环视频、圆角、阴影、外框、二维开场、额外光标强调与点击反馈。
- 场景预设保存/应用/默认；内部工程保存、另存、重开、最近工程及未保存保护。
- 有声MP4、静音MP4、仅音频M4A；尺寸和30/60FPS选项；进度、取消、错误提示；原始素材导出。

区域/设备来源、指定应用声音、完整 Mac 光标替换、原版3D开场及完整视觉对齐等仍有未完成部分。不要把未实现能力做成看似能用的按钮，也不要因为尚未实现就从产品清单删去。

自动运镜目前是可选项，Windows 开发版默认关闭。额外光标强调不能消除已烧入录屏的原生鼠标。静音动态背景不提供新的音频轨道。变速已使用保音高处理，但极高速音质不保证。这些是用户选择相关的真实边界，不应在改文案时变成不存在的承诺。

## 6. 必须保持的行为与接口

### 导航与文件安全

- 编辑器一直有明确的“返回录制”入口，返回时保留当前工程，可继续编辑。
- 打开其他工程、开始新录制、关闭应用时保留原有未保存保护；保存取消或失败不能继续覆盖当前工作。
- 录制、媒体保存、导出期间的按钮禁用与关闭处理继续有效。
- 重录/丢弃保留确认，不删除历史素材；移除最近记录不删除工程文件。
- `.dogscproject` 是项目文件夹，当前内部格式版本7兼容本项目旧版1–6；扩展名相同不代表 Mac 兼容，不改格式来迎合 UI。

### 媒体与时间线

- 保留真实视频 sink、摄像头和音频连接。不要新增第二套播放器来替代编辑器现有时序逻辑。
- UI 主题不应修改导出的背景、颜色、圆角或其他媒体设置。用户媒体画布与应用外壳是不同的呈现层。
- 主片段和运镜使用源时间/输出时间映射；拖动、裁短、变速以后不能简单按屏幕位置直接写源时间。
- 运镜拖动采用草稿，释放时一次提交；Esc取消；吸附开关与Shift临时绕过继续工作。
- 不随意修改 C++ 媒体算法、音频包时钟、变速与导出逻辑。确有与 UI 相关的问题，先说明根因再作最小必要修改。

### 快捷键与自动检查契约

保留以下 `objectName`，或在确有必要修改时同步修正调用方并验证：

`editorView`、`canvasPreview`、`editorPlayer`、`timelineStrip`、`timelineClip-<索引>`、`manualZoomTrack`、`manualSegmentMouse`、`unsavedEditorDialog`、`exportOptionsDialog`、`cropEditor`、`shortcutHelp`、`recentProjectsPanel`、`recorderMemoWindow`。

`Editor.inspectorTab` 当前索引为0片段、1画布、2相机、3运镜、4效果。测试会使用该属性；视觉分类可变，但不要无意改变这个契约。

`Editor` 的 `seek`、`playPause`、`requestOpen`、`requestOpenRecent`、`requestExport`、`saveProject`、`requestNewRecording` 等函数有实际调用方。尽量复用它们，不用新的按钮直接绕过保护调用底层接口。

Space、方向键逐帧、Shift加速逐帧、Ctrl+Z/Y、保存/打开/导出、S拆分、Q/W裁短、Delete、运镜复制粘贴、帮助和Esc必须继续按现有上下文工作。文字输入、下拉框、滑杆及模态浮层要保留焦点保护。新增浮层需加入相应快捷键阻止条件。

## 7. 当前设计基线与允许调整的范围

当前基线：背景 `#f3f5f4`，面板 `#ffffff`，文字 `#202624`，辅助文字 `#7e8984`，强调 `#2d6a53`，强调浅底 `#e4f2eb`，边框 `#e5e8e6`。字体 Microsoft YaHei UI，主要控件32–36逻辑像素高，录制主按钮44。

目标窗口1280×860逻辑像素，当前最小860×640；截图像素可能因系统DPI放大，不要误以为它们就是逻辑窗口尺寸。可以改进基线，但要统一到令牌与组件，避免每页各自定义一套颜色和间距。

允许：重组录制页面、紧凑悬浮形态、编辑器工具栏、导航、检查器、导出流程的视觉层级、辅助面板、图标、字体、留白、焦点/悬停/选中反馈。功能可以进入菜单或浮层，但常用入口要易发现，返回和主要操作要明确。

不要为视觉效果引入大规模新依赖；优先 Qt 现有能力和仓库内矢量/代码资源。避免会干扰媒体帧率的装饰性动画、复杂实时模糊及整屏反复重绘。若确需依赖，先明确理由与影响，不悄悄替换技术栈。

## 8. 工作方式与精简验证

1. 查看仓库状态，保留此前大量未提交改动；不得用 reset/clean/checkout 覆盖现有工作。
2. 阅读固定原版图片与当前界面，先列出本轮要解决的几项视觉问题和顺序。建议按共享控件→录制→编辑器→导出/辅助面板推进，而非一次无依据地重写全部逻辑。
3. 完成一轮连贯改造，及时构建并查看真实窗口。设计图可辅助，但最终必须落入可运行 QML。
4. 正常和小窗口下检查布局、滚动、文字截断、弹窗、焦点、禁用态和选中态。让预览保有合理空间，时间线不能被工具行挤掉。
5. 按实际改动选择必要检查，记录结果与未验收边界；不要重复跑与 UI 无关的整套媒体矩阵。

构建示例，替换成机器上的真实 Qt MSVC kit：

```powershell
& '.\scripts\build-windows.ps1' -QtRoot 'C:\Qt\6.8.3\msvc2022_64' -Deploy
```

脚本默认部署 `build/desktop/portable-ui`，根目录 `启动 ScreenPilot.cmd` 优先启动它。若该程序正在运行，不强杀可能有未保存工作的用户窗口；使用脚本 `-DeploymentDirectory` 参数部署到另一目录。不要并行运行多个共享构建目录的构建进程。

现有检查入口如下；先生成一份短片复用即可。输出目录应不存在或为空，原始日志另存，不提前写入输出目录。

| `--ui-snapshot-smoke-test <短片>` | 录制页、编辑器、导出面板、正常/最小窗口截图 | `--editing-result-directory <目录>` |

| `--editor-shortcut-smoke-test <短片>` | 按键、输入框与弹窗保护 | `--editing-result-directory <目录>` |
