# Windows 播放与导出性能修复

2026-10-13。本批使用一段约193秒、2560×1380、带内嵌声音及独立系统音轨的实际录制复现问题。私人素材、路径、机器信息、截图和原始日志均只保留在忽略目录。现有未提交工作与界面契约保持原状。

## 原因与修改

- `CanvasPreview` 原先逐个解码回调同步转换完整图像，倍速时积压并阻塞界面；现在只保留最新待显示帧，在合并后的预览任务中转换。`CropPreview` 的尺寸查询改用帧元数据，避免隐藏检查器为计算几何而触发整帧转换。
- 当前合成器使用 CPU `QImage`。本机对照中 D3D 解码后的读回开销显著，因此在未显式设置 `QT_FFMPEG_DECODING_HW_DEVICE_TYPES` 时默认使用 Qt 6.8 的逗号值禁用硬件解码。显式环境配置仍优先，编码器选择不变。该配置是 Qt 的私有 FFmpeg 配置面，升级 Qt 时需复核。[Qt 6.8 配置说明](https://doc.qt.io/qt-6.8/advanced-ffmpeg-configuration.html)
- `CanvasRenderer` 缓存静态背景、阴影与外框，键包含设置、素材尺寸、输出尺寸和壁纸版本；缓存上限64MiB。开场、屏幕运动、动态背景继续逐帧处理。实际像素对照覆盖缓存命中和失效，未降低导出尺寸或画质。
- `ExportController` 将一个源帧对应的多个输出时刻保存为紧凑区间，按编码器容量逐个合成，替代一次展开大量图像。解码暂停/恢复依据剩余输出帧数，编码待发队列上限24；跳过无需产生输出的重复回调，删除多余像素复制。没有抬高超时或简单扩大旧队列限制。
- 内嵌音频原先只在GUI定时器中写入输出设备，解码回调积压时PCM可能先触发1秒缓冲上限。现在回调及flush也按设备剩余容量及时写出，保持PCM顺序和原上限。独立音轨仍使用原混音时钟。
- 取消导出现在保持忙碌状态，等待Windows释放句柄并删除本次专属临时文件后才报告完成；失败明确报错，不删除其他导出文件。

## 同素材对照

窗口1280×860，监听音量为0但音频处理启用，未修改系统音量。以下为单机单次测量，绘制次数不等于显示器实际呈现帧数；解码回调和窗口交换次数另外记录，不混作预览FPS。

| 场景 | 修改前 | 修改后 |
| --- | --- | --- |
| 1倍速预览10秒 | 约26.2次画布绘制/秒，GUI计时器间隔P95 44.9ms | 约45.5次/秒，P95 26.5ms |
| 4倍速预览，要求15秒 | 实际86.2秒，仅7次画布绘制，最长GUI间隔74.0秒 | 最终构建15.03秒，约32.5次绘制/秒，GUI间隔P95 48.9ms、最长75.3ms |
| 原尺寸60FPS，前20秒保留声音导出 | 55.5秒 | 28.1秒，输出1200帧 |
| 固定1440p画布合成，30次均值 | 27.6ms | 9.9ms |

第一次仅合并预览任务的修改仍出现58.6秒阻塞；继续定位到隐藏裁剪几何查询的隐式转换后才消除长阻塞。保留这一失败迭代，避免将局部合成提速误报为整条播放链路修复。

## 验证与限制

Release构建通过；静态缓存与未缓存参考逐像素相同，外框、裁切、开场和摄像头合成检查通过。90°/270° surface旋转与presentation-only旋转的pending/转换后尺寸一致检查通过。

- 整段193.08秒素材4倍速导出耗时193.27秒；重新解码2896帧，60FPS，视频48.266667秒、音频48.270000秒，均从0开始。时长对齐不代表已完成主观音画同步验收。
- 12秒仅4个源帧、每帧跨3秒的稀疏素材导出成功，重新解码720帧、60FPS，音视频均12秒；编码待发队列峰值24。
- 12组导出选项回归通过，覆盖带声音、静音、仅音频、片段重排/多速度、摄像头偏移和结束隐藏；纯音保音高检查通过。
- 取消回归确认未发布目标文件且无临时MP4残留。此前第一次取消测试发现了残留，修复后复测通过。
- 预览音频回归通过：独立WAV两倍速、暂停/跳转/结束、旧PCM一倍速、20秒内嵌AAC四倍速。AAC阶段输出1,920,000字节PCM并到达结束，组合纯音约439.95Hz；这是PCM链路检查，不是声学回录。
- 两分钟1440p60生成源的15秒四倍速预览先复现内嵌音频缓冲超限；修复后同条件无音频错误，约22.3次绘制/秒，源时间推进约51.8秒，仍低于理想四倍速进度。不能用用户素材上的帧率改善替代这一高负载限制。
- 两分钟生成源后续完整播放推进至119.96秒，无音频错误；45秒观察窗口含到达末尾后的暂停时间，因此不使用总绘制次数除以45秒作为运行中FPS。最终用户素材四倍速复测15.03秒推进至59.82秒，无音频错误。

进一步媒体验证结果见[公开验证摘要](validation/public-results.md)。

实际源文件平均约47FPS，且原始帧时间间隔最高约567ms；编辑器不能恢复录制时未采集的画面。本批没有修改录制吞吐。4倍速预览仍未达到60FPS，软件解码会增加CPU使用；跨GPU、4K、多摄像头与复杂动态效果尚未完成性能验收。未采集GPU利用率，不据此推断GPU瓶颈占比。

导出仍通过正常速率的 `QMediaPlayer` 解码源片，倍速工程可能受源时长限制；没有用提高播放器速率来冒险跳过导出所需画面。原工程的“编码过慢”错误未在同一工程配置下复现，紧凑队列修复针对已定位的稀疏帧展开问题，不保证所有导出错误已消失。

## 本地复现与运行

根目录 `启动 ScreenPilot.cmd` 启动 `build/desktop/portable/ScreenPilot.exe`（本批构建产物，已由原 `portable-performance` 目录更名），即构建脚本 `-Deploy` 的默认部署目录。

使用自己的素材和空结果目录：

```powershell
ScreenPilot.exe --media-performance-test <source.mp4> --performance-result-directory <results> --performance-rate 4 --performance-seconds 15 --performance-no-export
ScreenPilot.exe --media-performance-test <source.mp4> --performance-result-directory <results> --performance-rate 4 --performance-export-only --performance-export-seconds 600 --performance-resolution source --performance-fps 60
```

性能探针保存素材路径等私人信息，请勿提交其输出。探针的 `success` 只表示功能流程完成，流畅度必须结合GUI间隔、绘制次数、阶段耗时及内存数据判断。
