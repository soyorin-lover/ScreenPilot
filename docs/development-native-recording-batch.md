# Windows 原生分辨率录制

2026-10-13。后端开发批次；最终界面继续交由 Claude 负责。本轮保留既有设计，仅在录制来源弹出面板连接规格选择。

## 行为与接口

`RecordingController` 新增以下 QML 属性：

| 属性 | 类型与取值 | 行为 |
| --- | --- | --- |
| `resolutionMode` | 字符串：`source`、`4k`、`1080p` | 默认原始分辨率；记忆到录制偏好；录制中不可修改 |
| `videoCodec` | 字符串：`h264`、`hevc` | 默认H.264；记忆到录制偏好；录制中不可修改 |
| `availableVideoCodecs` | 列表，项含 `label`、`value` | 按MP4容器、当前音频配置和本机编码能力列出；不是所有分辨率编码必定成功的保证 |
| `effectiveVideoSize` | `QSize` | 收到首个有效采集帧后计算的编码请求尺寸；实际文件尺寸以解码结果为准 |

分辨率由采集帧物理像素计算，避免混淆桌面逻辑尺寸与DPI缩放。`source`保留像素，只向下取偶数以满足编码要求；最高4K为横屏3840×2160/竖屏2160×3840，最高1080p为横屏1920×1080/竖屏1080×1920。按比例缩小，不放大较小来源。窗口边框可能属于采集帧，因此原生窗口素材不一定是常见预设尺寸。

视频目标码率按实际尺寸增加，范围4–48Mbps，音频链路继续沿用已修复的48kHz输出。码率是编码目标，不是所有后端的硬上限。

已保存但当前不可用的编码选择在开始时明确报错，不静默切换到其他编码。平台编码器拒绝尺寸时也保留错误提示，不把降级结果称为原生录制。ProRes暂未实现；帧率控制仍沿用此前路径，本轮不宣称已完成准确的30/60FPS录制控制。

## 原始分辨率导出

之前自定义画布比例的“原始分辨率”导出会使用预览设计尺寸，导致高分辨率素材降到1080p。本轮新增 `CanvasRenderer::nativeOutputSize()`，在裁切后的源像素范围内按画布比例计算输出，独立于预览设计尺寸。例如3840×2160素材使用1:1画布时，原始导出为2160×2160；小素材不被自动放大到1080p。

显式选择1080p、1440p和4K的导出方式继续保留。裁切、比例改变会改变成片尺寸，“原始”不表示总与未裁切文件宽高相同。

## 复现

使用现有 `scripts/build-windows.ps1 -QtRoot <Qt-MSVC-kit> -Deploy` 构建。启动器优先打开本批部署目录。录制页点显示器/窗口来源，设置面板内选择分辨率与编码；录制后的工程仍使用当前内部格式。

- `--recording-profile-smoke-test <空目录>`：生成运动网格窗口，真实录制原生与最高1080p两段，再解码核对采集帧、请求和成片尺寸；检查偶数、横竖屏、无放大、偏好保存和录制中锁定。若采集源未超过1080p，报告明确标记高分辨率覆盖未验证。
- `--native-export-smoke-test <空目录>`：生成2560×1440短片，使用1:1画布按原始分辨率导出，再实际解码检查1440×1440，确认突破旧1080p上限。

生成媒体、截图和运行日志保存在本地忽略目录，不公开个人桌面或机器信息。高分辨率长录制、所有GPU/编码器组合与HEVC真实录制需要分别记录验收，不以能力查询或构建通过代替。

## 实际结果

构建及Qt部署通过。真实生成窗口采集帧为2224×1307，原始模式成片解码为2224×1306（向下取偶数），最高1080p模式为1836×1080，保持来源比例；两段各解码113帧。偏好持久化、无效参数拒绝和录制中锁定检查通过。高分辨率覆盖为真实运行通过，不是仅检查请求参数。

2560×1440生成短片按1:1画布原始导出，成片解码1440×1440，突破旧上限；原生/4K/竖屏/裁切/小素材尺寸规则检查通过。本批真实录制验证使用H.264，完整3840×2160实机录制与HEVC实际录制未在本批逐项运行。
