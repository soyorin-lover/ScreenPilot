# 接近满帧优化：阶段检查点

用户要求因额度停止扩展工作。当前代码与已构建程序保留，未提交、未推送，未降低分辨率或码率。启动脚本继续指向 portable-performance。

## 已验证

- 1440p60生成素材、1倍速、15秒窗口：场景图提交的新画面从32.7提高到46.3次/秒，GUI计时器间隔P95从51.2降至25.1ms，最长无新画面间隔从241.1降至91.3ms。实际显示器呈现未作外部测量。
- 预览改为一个固定后台线程转换与合成，至多一个在途任务和最新待处理状态；GUI发布完成图像，裁剪预览不再隐式转换视频帧。
- 像素一致、50帧合并取最新、处理中清空、摄像头清空、旋转尺寸与处理中析构检查全部通过。
- 最新Release构建与diff检查通过。

## 录屏改动及待验证事项

20秒基线：原尺寸约48.8FPS，1080p约52FPS；采集回调约60FPS，GUI读回和编码交接损失帧。新增公开QAbstractVideoBuffer适配器，保持独立时间戳，在编码器消费时映射原始像素，裁切缩放也延后执行；测量通过共享原子计数器跨线程汇总。

同条件复测：原尺寸54.05FPS，较48.79FPS改善；1080p懒转换退步至35.08FPS，因此已恢复缩放/裁切的原同步实现，仅原尺寸全幅使用缓冲适配器。原始报告位于本地忽略目录 `probe-results/performance-20261013/full-rate/recording-buffer-after/recording-profile-smoke.json`。恢复后的缩放路径未重跑20秒性能对照；新录屏路径仍需暂停/继续、区域和带声音录制回归。不要宣称录屏已满帧。

## 未达标与下一入口

55FPS最低提交门槛仍未通过，不能宣称稳定接近60FPS，更不能宣称全部环节已完成。新实现尚未完成倍速与全部编辑交互复测。

预览转换与合成仍约14ms/帧，并存在后台完成后等待GUI重新派发的空档。下一步先量化这一空档，再评估单一最新请求/结果缓冲，让后台连续工作、GUI有界发布。Qt6.8软件帧toImage仍可能经过GPU上传/读回；禁用硬件纹理转换的环境变量不能解决这条路径，不应盲目添加配置或复制Qt私有转换代码。
