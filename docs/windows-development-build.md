# Windows 可运行开发版

2026-10-13：从独立技术实验转入产品流程开发。按用户要求缩减验证，优先交付可操作应用，阻止正常使用与数据可靠性的问题仍需修复。完整首版范围继续以固定 Mac 提交和95项能力清单为依据。

## 启动与使用

双击仓库根目录的 `启动 ScreenPilot.cmd`，或运行 `build/desktop/portable/ScreenPilot.exe`。此目录已带Qt运行依赖，移动时保留整个portable目录。本轮是内部开发版，没有安装器。

1. 选择屏幕或窗口。打开新窗口后，可刷新来源。
2. 可选开启默认麦克风，选择保存文件夹。
3. 点击开始录制，点击停止并保存。
4. 保存后可在应用内播放、拖动进度，或打开保存文件夹与系统播放器。

默认保存到Windows“视频”目录下的ScreenPilot文件夹。录制文件使用时间和唯一ID命名；不会覆盖既有视频。录制或保存过程中关闭主窗口，会先请求停止并完成保存。屏幕录制可能包含应用自身，可使用Windows最小化按钮移开主窗口；自动排除辅助窗口尚未实现。

## 构建

```powershell
& '.\scripts\build-windows.ps1' -QtRoot 'C:\Qt\6.8.3\msvc2022_64' -Deploy
```

传入自己的Qt 6.8 MSVC kit路径；Visual Studio通过vswhere自动查找，也可传 `-VisualStudioRoot`。示例路径为通用占位，不代表开发者本机路径。追加 `-Launch` 可构建后打开应用。源码入口为根CMakeLists.txt和app目录；probes仍为历史独立实验，不参与应用构建。

## 本轮必要验证

构建和Qt依赖部署通过。`ScreenPilot.exe --smoke-test <新的空目录>`只录制程序生成的自有动画窗口，停止保存后重新打开MP4并实际解码；没有录用户桌面或麦克风。结果记录在[公开验证摘要](validation/public-results.md)。检查成功不代表屏幕、麦克风、多设备、长录制或完整编辑链路均实测通过。

UI采用Qt Quick/QML，石墨色、米白交互色依据固定原版 `RecorderViews.swift` 和 `RecorderSurfaceStyle.swift`；当前布局为逐步实现过程，尚未完成原版界面验收。录制模块暂接Qt多媒体后端，后续可以替换，不将其视作完整音频/编辑架构已定案。

## 当前边界

本轮提供屏幕/窗口选择、画面录制与预览、可选默认麦克风入口、MP4保存、回看及保存位置选择。实际通过的是自有窗口无音轨录制—保存—解码；屏幕录制和麦克风入口已构建但未逐项运行验收。

尚未实现的原版能力继续保留：区域与设备来源、摄像头、系统/指定应用声音、真实媒体暂停、独立鼠标轨迹、工程保存与兼容、时间线编辑、美化与运镜、编辑后导出，以及其余能力清单条目。这不是完整首版发布。

当前录制尺寸保持比例并限制到1920×1080范围；30FPS为请求参数，历史实验的实际帧率偏差和W03A时钟问题仍未解决。系统音频本轮没有接入，播放视频不会进入本轮无麦克风录制的音轨。下一步在现有可运行应用上继续接工程与基础编辑流程，不扩展独立实验。
