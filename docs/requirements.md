# ScreenPilot 需求与路线图

文档版本：1.0
日期：2026-10-13
状态：Windows 产品代码开发中；按用户决定排除Mac工程兼容与iPhone/iPad输入，其余原版能力继续对齐。

本文描述首版对齐目标和阶段性完成条件。首版是完整对齐固定版本 Mac 原版的首个交付版本，不是精简 MVP；按用户明确要求排除Mac工程兼容。产品能力分批实现；具体平台环境、实现方案和性能阈值持续验证。按用户最新要求，减少独立实验与重复验证，优先交付可运行应用，优化随后推进。当前已有Qt Quick基础录制、编辑、美化、工程保存与导出流程，并已实测预览性能修复、系统声音录制及带音轨剪辑导出；必要构建、启动、保存与实际播放检查仍保留。未验证方案不记作已确定架构，完整首版范围不缩减。

## 1. 项目目标

开发 ScreenPilot：一个基于 C++ / Qt 的 Windows 桌面录屏与轻量编辑应用，Windows 版完成后再逐步移植 Linux，面向制作软件演示、操作教程和产品展示的用户。

以 GitHub 上固定版本的 Mac 版 DogSC 为产品标准，使用 C++ / Qt 先在 Windows 上完整对齐其功能、界面、工作流程、编辑行为、编辑时间语义、运镜算法和成片效果。通过真实交付记录展示个人使用 AI 完成需求、技术决策、实现、验证和发布的工程能力。

主要场景包括个人开发者展示软件、带麦克风讲解的操作教程，以及需要系统声音和摄像头的产品演示。个人开发者是重要使用者，不据此排除原版其他场景或缩减功能。核心问题是让用户先在 Windows 上获得原版从录制、保存、编辑、美化到导出的一体化体验。

成功不以代码量、AI 对话数量或界面截图衡量，而以用户流程可用、Windows 实测验证、数据可靠和结果可复现衡量。

### 1.1 参考优先级

1. 用户在本项目中明确提出的目标与调整。
2. 固定版本的 Mac 原版源码、工程数据和算法。
3. 对应版本的 Mac 应用实际行为、截图与演示素材。
4. 官方平台文档与技术验证结果，用于确定平台差异及可行实现。
5. 已有 Electron Windows 版，仅作辅助案例。

上游参考仓库：[laogou717/dogsc](https://github.com/laogou717/dogsc)。初始源码基线：`fa24059a9ba7e769152b3c1de047d96aca873e1c`。

上游 main 更新不能自动改变本项目需求。更新参考基线时，先记录模型、算法、功能和资源变化，再决定同步范围。

### 1.2 对齐的三个层次

| 层次 | 目标 | 验证方式 |
| --- | --- | --- |
| 界面与工作流程 | 窗口布局、控件、设置、录制、保存、编辑、导出及常用快捷操作对齐原版 | 对应页面截图、固定操作脚本与实际试用 |
| 算法和数据 | 时间线、自动缩放、插值与光标行为对齐，工程格式独立 | 固定输入输出、边界测试、本项目工程往返测试 |
| 视觉结果 | 构图、运镜节奏、光标、圆角、阴影等肉眼接近参考 | 同素材、同参数、指定时间点的帧与视频比较 |

不承诺不同系统的字体、编码器和图形后端逐像素一致。数值容差与视觉验收样例在相关功能实现前制定。

操作系统权限面板、快捷键映射和窗口装饰需要平台适配；应用内布局、光标效果与交互仍以原版为标准。影响产品体验的差异应有验证依据并由用户确认。

## 2. 范围与版本边界

### 2.1 首个内部演示版

内部演示版是开发途中的验证里程碑，不能作为完整首版发布，也不能改变首版对齐范围。具体开发顺序在第 3 步确定，以下仅为可用流程的示例。

用于证明项目结构和最小编辑流程，不作为完整录屏产品发布：

- Windows 可构建并打开 Qt 应用。
- 显示素材预览和基础时间线。
- 使用固定测试素材，分割、裁短并导出；测试素材加载是内部验证手段，不据此增加原版未确认的“任意视频导入主轨”产品功能。
- 运行核心模型、时间映射和序列化测试。

此阶段不宣称工程完全兼容、实时采集完成或性能达标。

### 2.2 完整首版的基础能力

本表与 2.3 节共同构成首版能力范围。它们按开发阶段逐项实现，不能将仅完成本表的版本称为完整首版。

| 编号 | 能力 | 完成条件 |
| --- | --- | --- |
| R01 | 屏幕录制 | 可选来源、开始、停止；素材可读；异常有明确结果 |
| R02 | 区域录制 | 选区与最终画面一致，正确处理 DPI 和显示器坐标 |
| R03 | 窗口录制 | 在支持的平台采集所选窗口；限制明确，不把固定区域截图冒充独立窗口采集 |
| R04 | 声音 | 麦克风与系统声音可选择；与视频对齐；设备失败不会无提示丢失声音 |
| R05 | 鼠标数据 | 独立保存位置和点击；与素材时间同步；能识别能力缺失 |
| R06 | 工程保存 | 录制后保存、重新打开、继续编辑；失败不破坏已有工程 |
| R07 | 基础剪辑 | 播放、定位、分割、裁短、删除、变速、撤销和重做 |
| R08 | 运镜 | 自动缩放与跟随、手动缩放；对应核心规则与上游参考对齐 |
| R09 | 画面设计 | 比例、留白、背景、圆角、阴影和基础光标美化 |
| R10 | 视频导出 | MP4、1080p 与 4K、30/60 FPS 选项；实际能力检测；进度与取消 |
| R11 | 录制标记 | 录制中添加、工程中保存、编辑时定位；不进入成片 |
| R12 | 可靠性 | 清楚显示权限、设备、磁盘、编码和损坏素材错误；保留可恢复数据 |

完整首版仅在声明支持的 Windows 环境验收。Linux 移植在 Windows 版完成后进行，不作为当前首版验收前提。若某功能受平台限制，应提供真实验证依据、影响和替代方案，由用户确认差异；不能自行调整范围或静默降级。

### 2.3 完整首版的其余原版能力

原草案将以下能力放入首版之后，现纠正为首版必须对齐的范围：

- 摄像头录制、布局与运动轨。
- 屏幕 3D、透视、倾斜、聚焦虚化与开场动画。
- 贴图、画面柔化、裁切、样机外框、动态背景和场景预设。
- 时间线重排、吸附、缩略图、波形与效果复制粘贴。
- 原始素材分辨率、1440p、M4A 音频导出及更多编码策略。
- 悬浮备忘录、中英文界面切换和 Windows 更新机制。Linux 支持属于 Windows 版完成后的移植阶段。

这些能力与 2.2 节同属首版。详细行为与源码依据见[原版能力对齐清单](parity-checklist.md)，覆盖录制、编辑、工程、导出、设置和界面。该清单区分源码确认与 Mac 未实测，分组摘要不替代逐项验收。上游 main 的新增能力只有在更新基线后才改变范围。

源码盘点补充的首版能力包括：HEVC/H.264/ProRes 422 录制编码、录制分辨率限制，全部系统声音与所选应用声音范围，桌面项目/Dock隐藏和辅助窗口排除，暂停/继续、重录/丢弃、中断恢复、源文件导出、摄像头全片与分段同步。原版iOS设备来源按用户最新决定排除。其余平台路径持续验证，不能因旧摘要未列出而排除。已确认背景视频导入及替换已有摄像头素材；尚未发现任意视频作为新主轨工程导入入口，不将其冒充原版能力。

品牌文案、作者赞赏入口、Apple 专属更新和分发设施不直接照搬；语言、设置、更新等用户流程应提供本项目的对应体验。任何实质功能差异都需记录依据并由用户确认。

首版后的迭代用于修复、优化、扩展平台和评估上游新版本，不能默认承接固定基线中尚未完成的功能。

### 2.4 首版不做

以下限制针对原版之外的扩展，不用于排除固定基线已有能力：

- 通用专业视频编辑器、多机位制作、云协作或账号系统。
- Linux 实现、验证、打包与发布；待 Windows 版完成后再逐步移植。ARM64 和 Linux 全发行版、全桌面环境的全面兼容不属当前范围。
- macOS 客户端重写。
- Mac工程兼容、格式转换或与Mac原版双向互通。
- iPhone/iPad/iOS设备画面与设备声音输入（用户明确取消）。
- 为展示 AI 而添加与录屏编辑无关的 AI 功能。
- 为兼容已有 Windows 适配版而偏离 Mac 原版工程语义。

## 3. 平台与技术约束

### 3.1 目标平台

| 平台 | 初步验证范围 | 重点 |
| --- | --- | --- |
| Windows x64 | Windows 11；Windows 10 后续评估 | 原生窗口采集、DPI、声音、GPU 编码 |
| Linux（Ubuntu） | Windows 版完成后再确定版本与桌面会话 | 当前不实现或验证；后续移植时单独制定计划 |

Windows 是当前唯一交付和验证平台。Linux 不参与当前技术风险验证、构建、测试或发布门槛；Ubuntu/Wayland/X11 的具体工作待 Windows 版完成后再展开。

### 3.2 已选与未选事项

**已选：** C++、Qt、Windows 优先完整交付、Mac 原版作为主要参照；Linux 后续移植。

**技术输入：** 按用户选择使用 Qt 6，当前实验采用 C++20、Qt 6.8.3、CMake；产品界面方向为 Qt Quick / QML。具体产品 Qt 小版本、编译器和 SDK 在对应验证后锁定；实验使用 Widgets 不构成产品界面架构决定。

**待技术验证后决定：** 采集具体 API、GPU 合成与纹理共享方式、音频后端、FFmpeg 的使用边界、编码与依赖分发方式。

不默认承诺零拷贝、全硬件编码、恒定 60 FPS 或免安装依赖。这些能力必须通过实际设备验证。

### 3.3 模块边界候选（第 3 步再确定）

以下保留为设计输入，尚未形成架构决定，本轮不展开实现计划。

- 核心层：项目模型、时间映射、剪辑命令、鼠标与运镜、场景计算，可独立测试。
- 应用层：录制与编辑流程、工程管理、任务取消、设置和错误呈现。
- 界面层：Qt Quick 录制条、编辑器、检查器、项目库。
- 平台层：当前只实现 Windows 采集、声音、输入和窗口能力；Linux 后端在后续移植阶段确定。
- 渲染与导出层：消费同一份场景结果，共用效果规则，明确资源与线程归属。

避免将 Windows 句柄放入持久化工程模型；保留自然的系统边界，不为尚未开展的 Linux 移植预建复杂抽象。视频处理不得阻塞界面线程；队列与缓存需要有界，不能随录制时长无限增长。

## 4. ScreenPilot 工程与核心算法对齐

### 4.1 工程格式

用户明确取消 Mac 工程兼容要求，不实现原版工程读取、格式转换、另存回 Mac 或双向往返验证；它们不再属于首版范围或后续默认任务。原版功能、界面、编辑行为、运镜与成片效果仍作为对齐目标。

ScreenPilot 独立维护工程格式，当前内部版本7，可读取本项目版本1–6。验收保存、重新打开、继续编辑、媒体资源复制、内部旧版本默认值与失败保护。拒绝 Mac、未知生产者及未来版本工程，不能因扩展名相同而尝试覆盖。内部格式迁移仍应保护已有数据，损坏或缺失素材应明确报错。

### 4.2 算法对齐

- 先记录上游文件和提交，再改写为可测试的 C++ 实现。
- 测试覆盖点击分组、持续移动、静止、边界位置、剪切点、变速、空输入及异常数据。
- 时间统一转换到有明确定义的素材时间和输出时间；不同系统时钟不能直接混用。
- Swift 原版输出可作为对照，但必须先证明测试工具能够正确运行。没有运行结果时，不把“已读取源码”写成“已对照验证”。

## 5. 质量与验收

### 5.1 验证原则

- 每项功能有可复现的输入、步骤、预期结果和实际结果。
- 区分构建通过、功能通过、性能通过与特定硬件验证通过。
- Windows 验收记录系统版本、CPU/GPU、驱动、屏幕分辨率和缩放比例；Linux 的环境与测试记录在后续移植阶段建立。
- CI 负责构建和自动测试；真实桌面采集、音频和 GPU 行为在实际环境验收。

### 5.2 首版必须检查的场景

- 连续录制与反复开始/停止；检查时间漂移、丢帧、资源增长和素材可读性。
- 多显示器、混合 DPI、负坐标、窗口移动与调整大小。
- 采集权限拒绝、选源取消、设备断开、磁盘满、编码失败和导出取消。
- 剪切与变速后声音、光标和运镜仍与画面对齐。
- 工程保存失败、应用异常退出、损坏或缺失素材时的数据保护。
- 预览与导出使用同素材、同参数、同时间点比较。
- GPU 路径不可用时明确回退或说明限制，不留下无限等待的进度条。

### 5.3 性能基线

目标场景为 1080p60 录制、原版效果组合预览和 4K 导出。先在第 2 步建立测量方法与参考机器，再冻结掉帧、同步误差、交互延迟、内存和导出速度的验收阈值。

现阶段不提供未经测量的性能数字。测量至少记录帧时间/掉帧、音画偏移、鼠标偏移、CPU/GPU、内存及导出耗时；10 分钟连续录制纳入首版验收。

### 5.4 完整首版的完成检查

| 检查项 | 可检查的验收要求 |
| --- | --- |
| 能力覆盖 | 固定基线的每项用户能力均登记来源、操作步骤、预期行为和 Windows 结果；无未完成项。用户确认的平台差异另列，不能将其计为完全一致 |
| 完整流程 | 声明支持的 Windows 环境完成屏幕、窗口、区域录制，组合声音与摄像头，保存、重开、剪辑、运镜、美化并导出；记录素材与实际结果 |
| 编辑与效果 | 对 2.2、2.3 节各能力使用固定素材逐项操作，比较参数、默认值、时间线行为、撤销重做、预览与导出；组合效果也需检查 |
| 界面与交互 | 对照固定版本的录制、编辑、设置和导出界面，逐页比较布局、控件、快捷操作和状态提示，记录并处理差异 |
| 工程可靠性 | ScreenPilot工程保存重开、内部旧版本读取、媒体复制与失败保护通过；Mac和未知/未来版本工程被明确拒绝，不破坏已有数据 |
| 导出 | 对基线支持的 MP4/M4A、分辨率和帧率选项建立测试矩阵；输出可解码，音画与鼠标同步，进度和取消有效 |
| 可靠性与性能 | 5.2 节异常场景逐项记录结果；参考机器与第 2 步确定的性能阈值有实测证据；失败不破坏已有工程 |

以上为产品验收要求，尚未执行完整产品验收。独立探针结果见 [Windows 技术风险计划](validation/windows-risk-plan.md)。源码能力盘点见[原版能力对齐清单](parity-checklist.md)；Mac 实测、参数边界的完整样例、数值容差和参考素材尚待补齐，不能据此宣称需求细节已全部冻结或功能已验证。

## 6. 开发路线图

按用户确定的六步顺序推进，不按未经验证的工期承诺推进。按用户最新要求缩减独立实验，采用轻量结构进入第 4 步可运行流程开发，必要验证随功能完成；第 2 步未解决的风险继续跟踪，不视作已通过。

| 阶段 | 工作 | 退出条件 |
| --- | --- | --- |
| 1. 定义第一版 | 明确用户、问题、场景、完整原版对齐范围、非目标和验收要求；核对固定基线能力 | 项目说明、README 与需求路线图一致；能力范围有依据，待核对细节明确，未擅自删减原版能力 |
| 2. 验证技术风险（随开发继续） | 验证 Windows 录屏、音频、鼠标同步、渲染和视频导出；确定系统环境与性能阈值 | 留下小型验证程序、运行结果和能力矩阵；关键风险有结论，差异有依据 |
| 3. 确定结构与计划 | 确定核心与 Windows 系统代码边界、工程模型、架构说明、能力对照表和任务列表 | 每项原版能力有任务与验收对应；分批交付顺序明确，完整首版范围保留 |
| 4. 按完整流程开发（当前） | 分批交付可实际使用的录制、编辑、效果、保存与导出流程，直至覆盖基线全部能力 | 各批有代码、测试和真实运行记录；内部演示版与完整首版明确区分 |
| 5. 验收与修复 | 执行固定场景、原版界面与效果比较、Windows 性能、异常恢复和本项目工程保存重开检查 | 5.4 节逐项有证据；缺陷处理、测试记录与已知差异完整，无未处理的数据破坏缺陷 |
| 6. 发布与迭代 | 制作安装包、变化记录、许可清单与使用说明；确定下一版范围 | 可复现构建与安装，首版能力验收完成，差异已确认；下一版不默认承接基线欠缺功能 |

第 2 步只验证 Windows 录屏、音频、鼠标同步、渲染和导出路径，包括原版设备来源及编码选项的对应能力。若遇到限制，先尝试替代实现；确需影响范围或体验时，带着结果与用户讨论，不自行缩减首版。当前按[风险计划](validation/windows-risk-plan.md)逐项执行并记录结果。

Windows 完整版完成验收与发布后，再启动 Linux 移植：届时确定 Ubuntu 基线、验证采集/声音/输入/渲染差异，逐步实现并独立验收。当前不安排 Linux 后端、构建流水线或打包任务。

## 7. AI 协作与个人工程流程

每个任务遵循：明确范围与验收 → 实现 → 评审 → 测试 → 记录证据 → 提交版本。

- AI 任务写清输入、允许修改的模块、输出和完成标准。
- 独立模块可以并行；共享接口先定义，合并后由主线统一验证。
- 实现与评审分开，避免仅由代码作者自述“已完成”。
- 重要决策记录问题、选项、理由、代价和验证依据。
- 不把模拟数据、界面占位或仅编译通过包装成完整 Windows 功能；Windows 测试不代表已支持 Linux。
- 文档随功能更新；未执行的测试标注未执行，已知缺陷保留追踪。

## 8. 风险与应对

| 风险 | 应对 |
| --- | --- |
| Windows 采集、应用声音隔离或鼠标同步不能达到原版行为 | 第 2 步在 Windows 单独验证，保留结果和替代方案；不自行删减原版能力 |
| 本项目工程损坏、内部版本迁移或媒体缺失 | 内部工程往返验证、迁移保护、明确错误与恢复路径；不实现Mac格式兼容 |
| GPU、颜色与 HDR 跨平台差异 | 核对基线实际支持行为，使用固定色彩素材验证；不能未经确认自行限定 SDR 或省略原版能力 |
| 预览与导出不一致 | 共用场景与效果规则，固定帧比较 |
| 原生线程与资源生命周期错误 | 明确所有权、队列上限与取消流程，加入重复操作与异常测试 |
| 完整对齐工作量大，或内部版本被误当最终交付 | 分批交付完整小流程，持续追踪基线全部能力；最终首版仍需完成完整对齐 |
| AI 生成代码能编译却不可靠 | 独立评审、回归测试、真实设备验证和证据记录 |
| 上游迭代造成持续返工 | 固定基线，按版本评估同步，不追随每个提交 |
