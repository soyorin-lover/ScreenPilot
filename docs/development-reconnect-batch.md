# Windows UI 与媒体链路修复

2026-10-13。保留 Claude 第二轮界面设计，修复功能状态与后端连接，并处理用户反馈的系统声音漏录、杂音与视频回放负担。

## 已定位与修改

- 分段选择控件原先直接给 `currentIndex` 赋值，会解除调用方的绑定；现只发出选择意图，由工程状态更新选中项。撤销、预设和切换工程后可继续同步。真实鼠标点击回归在修改前失败、修改后通过。
- 录制入口等待屏幕、摄像头及上一段媒体移交完成，避免上一段摄像头还在保存时开始下一段。
- 设置弹出面板的再次切换可关闭；保持点击外部和Esc关闭逻辑。
- “先保存再录制/关闭”现在等待真实保存结果继续；失败或取消会清除待办动作。
- 手动运镜输入范围与后端一致：倍率1–6，焦点0–1，进入/退出0–5秒。
- 音频实测发现：44.1kHz端点的位置每包增加441，而自动转换后的48kHz PCM每包为480帧。原来直接使用位置差会重叠并逐渐落后于输出，造成缺口与边界杂音。现在按端点混音采样率换算位置，48kHz输出格式不变。
- 原100毫秒WASAPI缓冲在180毫秒界面阻塞检查中出现最长80毫秒缺口；改为500毫秒容量，输出仍使用原有10毫秒块和60毫秒到达余量。缓冲容量与固定延迟不是同一回事；超过容量的长阻塞仍可能丢失，不声称后台实时线程隔离已完成。
- 最近录制的1080p媒体达到约60Mbps；改用平均码率模式，按分辨率设置4–12Mbps视频目标和192kbps音频目标，降低写盘及回放负担。目标码率不是所有后端的硬上限，实际以成片检查为准。

Windows音频接口依据：[IAudioCaptureClient::GetBuffer](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudiocaptureclient-getbuffer)、[IAudioClient::GetMixFormat](https://learn.microsoft.com/en-us/windows/win32/api/audioclient/nf-audioclient-iaudioclient-getmixformat)。采样率差异和缺口结论来自本机实际包诊断与生成纯音检查，不将设备行为推广为所有驱动的保证。编码选项依据：[Qt QMediaRecorder](https://doc.qt.io/qt-6/qmediarecorder.html)。

## 必要复现

用现有构建脚本部署，启动根目录启动器选择的最新修复目录。详细日志、音频、截图仅保存在忽略目录，不公开。

`--audio-packet-smoke-test` 包含44.1kHz位置→48kHz PCM的长序列换算及既有丢包/时钟错误检查。

`--audio-continuity-smoke-test <空输出目录>` 播放低音量生成纯音，仅采系统混音，不启用麦克风或采集桌面；分别检查普通采集与五次180毫秒界面阻塞。报告每20毫秒的能量、纯音分量和缺口。其他应用声音也会进入系统混音，纯音频点受干扰的窗口单独记录；该检查不是声学听感或全频失真验收。

`--audio-smoke-test <空输出目录>` 录制生成动画及声音并实际导出、解码。`--recording-controls-smoke-test <空输出目录>` 检查暂停、继续、重录与丢弃。

## 边界

本轮构建部署通过；持续性普通采集与五次180毫秒阻塞均为0缺口；实际系统声音录制、剪辑导出重新解码通过；暂停录制成片3.000秒、音轨3.008秒、暂停画面0帧，重录/丢弃通过。分段控件真实点击及外部状态更新回归3项通过。生成1080p预览短测渲染平均7.96毫秒、最大10.04毫秒、提交间隔P95为18.03毫秒；该测量不包含完整真实文件解码/显示耗时，不能用于宣称全面60FPS稳定。

Claude界面正常/最小窗口及导出面板截图检查通过；实际编辑器跨片段变速播放、合成摄像头同步、快捷键及文字保护、最近工程未保存保护通过。新保存继续分支完成函数级成功/失败/取消检查，未逐项操作真实系统保存对话框；真实摄像头延迟保存竞态仅完成保护条件检查，不冒充硬件验收。

此前短检查只检测音轨存在及测试音峰值，无法证明整段录制连续；此次新增持续性检查补上该缺口。修复前持续测试有91个异常20毫秒窗口，最长连续缺失1.82秒。单机短测不代表全部驱动、长录制或默认输出设备热切换验收。

现有CPU编辑预览仍有开销；原始录制帧率请求与后端实际输出也仍需单独对齐。不把降低码率等同于所有场景视频流畅度已解决。摄像头硬件本机未验收。Linux与Mac工程兼容不在本轮范围。
